# C Mini Redis 학습 안내

이 학습은 저장소의 `README.md`, `docs/DESIGN.md`, 소스 코드와 `reports/VERIFICATION.md`에 기록된 구현·검증 범위를 기준으로 한다. 객관식은 파트별 10문항, 7개 파트 총 70문항이며 한 번에 한 문항씩 제시한다. 학습자가 답하면 정오와 근거를 설명한 다음 다음 문항으로 넘어간다. 정답이나 이후 문항의 선택지는 미리 공개하지 않는다.

## 파트별 계획

| 파트 | 문항 | 다룰 내용 |
|---|---:|---|
| 1. 아키텍처와 AE 이벤트 루프 | 10 | 단일 스레드 poll 루프, 파일 이벤트·타이머, 모듈 책임, pipeline 실행 순서 |
| 2. RESP와 네트워킹 | 10 | 증분 파싱, 바이너리 bulk, 불완전 프레임·오류 연결 처리, 입출력 버퍼 |
| 3. 자료구조와 TTL | 10 | typed object와 dict, list/set/hash/zset, 만료와 approximate LRU 축출 |
| 4. Lua와 락 원자성 | 10 | KEYS 제한, 실행 자원 제한, 오류 후 변경, 소유 토큰 락 |
| 5. RDB 저장·복구 | 10 | fork 스냅샷, canonical RDB v9, CRC64, 만료 키 제외 복구 |
| 6. 캐싱 패턴 예제 | 10 | cache-aside와 메모리 큐 write-back의 재시도·종료 동작 |
| 7. 테스트와 성능 해석 | 10 | O2 및 ASAN/UBSAN 검증 범위, 독립 검사, 벤치 지표와 한계 |

각 답변 뒤에는 선택 결과와 구현 근거를 설명한다. 설명형 확인은 객관식 답변과 별도로 주요 함수의 역할·호출 흐름·예외 처리를 말로 풀어보도록 진행한다.

## 주요 함수 역할 목록

| 모듈 | 함수 | 역할 |
|---|---|---|
| `ae.c` | `ae_run` | poll 기반 이벤트 루프에서 파일 readiness와 주기 타이머를 처리한다. |
| `networking.c` | `parse` | 입력 버퍼에서 RESP 배열·bulk 요청을 증분 파싱한다. |
| `networking.c` | `commands` | 완성된 명령을 연결별 순서대로 실행하고 응답을 출력 버퍼에 쌓는다. |
| `commands.c` | `execute` | 명령 인자 검증, DB 작업, RESP 응답 생성을 수행한다. |
| `dict.c` | `lookup` | 바이너리 키를 고정 버킷 해시 테이블에서 찾는다. |
| `db.c` | `expirecycle`, `evict` | 만료 키를 정리하고 메모리 상한 초과 시 후보 표본 기반 approximate LRU 축출을 수행한다. |
| `scripting.c` | `evalcmd` | 제한된 Lua 환경에서 스크립트를 실행하며 키 선언·메모리·시간·명령 제한을 적용한다. |
| `rdb.c` | `savefile`, `loadfile` | canonical RDB v9를 CRC64와 함께 저장하고 지원하는 형식의 파일에서 복구한다. |
| `rdb.c` | `backgroundsnapshot` | fork 기반 주기 스냅샷을 관리한다. |
| `server.c` | `main` | 옵션과 서버 자원을 초기화하고 각 모듈을 조립해 이벤트 루프를 시작한다. |

## 설명 평가 기준

학습자가 함수, 명령 또는 자료 흐름을 설명하면 아래 다섯 항목을 각각 0~2점으로 평가한다. 총점은 10점이다.

| 항목 | 0점 | 1점 | 2점 |
|---|---|---|---|
| 정확성 | 역할이나 계약을 잘못 설명함 | 핵심은 맞지만 일부 부정확하거나 빠짐 | 구현 및 문서의 계약과 일치함 |
| 흐름 | 호출·데이터 흐름을 설명하지 못함 | 주요 단계 일부를 설명함 | 입력부터 결과까지 순서를 연결해 설명함 |
| 예외 | 예외·경계 조건을 언급하지 않음 | 한두 가지를 언급하나 처리 결과가 불명확함 | 관련 오류·경계 조건과 실제 처리 결과를 설명함 |
| 원자성 | 변경의 가시성·부분 반영을 잘못 설명함 | 일부 상황만 설명함 | 명령/Lua의 실행 중 끼어들기와 오류 전후 변경 규칙을 정확히 구분함 |
| 테스트 | 근거가 되는 검증을 제시하지 못함 | 관련 테스트나 검증 결과를 일부 언급함 | 구체적인 테스트 범위와 검증 한계를 함께 설명함 |

해당 주제에 적용되지 않는 항목도 생략하지 않고, 왜 적용되지 않는지 설명했는지에 따라 점수를 준다. `VERIFICATION.md`에 적힌 통과 결과는 확인된 범위를 의미하며, ASAN/UBSAN 통과만으로 누수 부재나 미검증 외부 도구 검증까지 주장할 수는 없다.
