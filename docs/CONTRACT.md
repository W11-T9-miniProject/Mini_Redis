# 구현 전에 정할 계약

## 계층별 책임

```text
recv → 연결별 input 버퍼
     → resp_parse(input): 완성된 명령 1개 + consumed
     → command_execute(command, now_ms)
     → store: 만료 판정/명령 의미
     → hash_table: 키 비교/충돌 처리/할당/삭제
     → RESP 응답을 새 메모리에 생성
     → 연결별 output 큐
     → send: 부분 전송을 이어서 처리
```

- `hash_table`은 네트워크와 시간을 모릅니다. expires_at은 보관만 합니다.
- `store`는 socket/RESP를 모릅니다. now_ms를 전달받아 시간 판단만 합니다.
- `resp`는 저장소를 모릅니다. 바이트의 형식만 해석합니다.
- `command`는 클라이언트 FD를 모릅니다. 저장소 상태를 프로토콜로 바꿉니다.
- `server`는 하나의 스레드에서 명령 실행과 만료 정리를 호출합니다.

## 지원할 명령

명령 이름/옵션은 ASCII 대소문자를 구분하지 않습니다. 키/값은 대소문자를 구분합니다.
키와 값은 바이트열이며 빈 키/빈 값도 허용합니다. 여러 키 DEL, PING 인자, NX/XX,
RESP3, 중첩 배열, inline protocol은 이 과제의 지원 범위 밖입니다.

| 명령 | 인자 수(argc) | 성공 응답 | 없는 키 |
|---|---:|---|---|
| PING | 1 | `+PONG\r\n` | 해당 없음 |
| SET key value | 3 | `+OK\r\n`, 기존 TTL 제거 | 새로 생성 |
| SET key value PX milliseconds | 5 | `+OK\r\n`, 양수 TTL 설정 | 새로 생성 |
| GET key | 2 | bulk string | `$-1\r\n` |
| DEL key | 2 | `:1\r\n` | `:0\r\n` |
| EXPIRE key seconds | 3 | `:1\r\n` | `:0\r\n` |
| TTL key | 2 | 남은 ms를 초로 내린 정수, 무기한은 -1 | `:-2\r\n` |

EXPIRE는 0 이하이면 삭제합니다. SET PX는 0 이하이면 오류이고 기존 값은 그대로 둡니다.
초→ms 변환과 now+ttl은 int64_t overflow를 검사합니다. 정수 인자는
선택적인 '-'와 1개 이상의 십진 숫자만 허용하며 공백/접미사/'+'는 거부합니다.

오류는 `-ERR <고정 문구>\r\n`입니다. 테스트는 구체 문구보다 오류 타입을 검증합니다.
명령 오류는 연결을 유지합니다. RESP 형식 오류/크기 초과는 오류 응답 후 종료합니다.
메모리 부족으로 오류 응답조차 만들 수 없으면 해당 연결을 닫되 서버 전체는 유지합니다.

## 메모리와 반환값

- `MrSlice`: 빌린 메모리입니다. 호출자가 free하지 않습니다. len=0이면 data=NULL 허용.
- `MrBuffer`: 소유 메모리입니다. `{0}`으로 시작하고 `mr_buffer_free`로 정리합니다.
- ht_set: 입력을 복사합니다. 호출자가 입력 배열을 바꿔도 저장 값은 보존되어야 합니다.
- ht_find/store_get: 내부 참조입니다. 저장소 변경 전까지만 사용합니다.
- resp_parse: args는 input을 참조합니다. 파싱 후 실행을 마칠 때까지 input을 이동하지 않습니다.
- init 실패 시에도 destroy가 가능해야 합니다. 해제 후 구조체는 빈 상태로 되돌립니다.
- output 매개변수는 실패 시에도 안전한 기본값으로 초기화합니다.
- MR_NEED_MORE는 파서의 정상 대기 상태입니다. 잘못된 입력과 다릅니다.
- command_execute의 MR_OK는 'RESP 응답 생성 성공'입니다. 오류 응답일 수도 있습니다.

테이블 불변식: 모든 노드는 정확히 한 버킷에 속하고, 동일 키는 하나만 존재하며,
size는 노드 수와 같습니다. 실패한 저장/확장은 기존 키·값·TTL을 보존해야 합니다.

## 시간과 동시성

now_ms >= 0, 무기한 expires_at_ms=-1, 만료 조건은 now_ms >= expires_at_ms입니다.
실행 시 CLOCK_MONOTONIC을 사용하고 테스트에서는 정수를 직접 전달합니다.
단일 스레드만 저장소를 변경합니다. 별도의 만료 스레드를 추가하면 이 전제가 깨집니다.
단일 명령은 다른 명령과 섞이지 않지만 GET→계산→SET 전체를 원자적으로 보장하지는 않습니다.

만료 정리는 버킷과 별도의 노드 순환 목록을 사용합니다. budget는 노드 확인 수입니다.
삭제 시 순회 커서를 보정하고 resize 시 순환 연결을 유지합니다.

## 첫 버전 상한

한 요청 프레임은 1 MiB, 인자는 최대 8개, 연결은 최대 128개,
연결별 출력 대기는 최대 4 MiB로 시작합니다. 헤더의 상수를 조정해 실험할 수 있습니다.
입력 버퍼 상한과 pipeline 처리 전략도 N03에서 정합니다. 여러 정상 프레임의 합이
1 MiB를 넘었다고 첫 프레임 자체를 잘못된 요청으로 처리하지 않도록 주의합니다.
저장소 전체 메모리 상한/eviction은 아직 없으므로 추가 과제로 기록합니다.
