# 자리 선점 시연

## 구성

```text
휴대폰 브라우저 → Flask 웹 서버(8090) → C Mini Redis HTTP API(8080)
                                      → 직접 구현한 해시 테이블과 변경 로그
```

전체 배치도는 제공된 이미지의 좌석 사각형을 따라 36개로 구성했다.
그중 회색 32개는 실제 Mini Redis에 기한 없이 사전 배정하고,
2팀-2(왼쪽 끝자리)와 11팀-1(오른쪽 끝자리)는 비워 둔다.
오른쪽 위 두 칸은 팀에 속하지 않는 공석으로 표시하고 선택·배정 취소 대상에서 제외한다.
1~10팀은 세 자리, 11·12팀은 두 자리이며 모든 화면에서 `팀번호팀-자리번호` 이름을 사용한다.
번호는 각 구역의 왼쪽 위에서 아래로 내려가 하단을 돌고 오른쪽으로 올라가는 순서다.
코치님 자리는 안내 표시이며 선택 대상에 포함하지 않는다.
회색 자리를 화면에서만 가짜로 비활성화한 것이 아니다.

배치 좌표는 `web/layout.py`에 분리했다. 팀별 세부 자리 이름은 실제 명단 확정 시
이 파일에서 조정할 수 있다. 현재 사전 배정 이름은 실제 교육생 이름이 아닌
`기존 배정`이라는 시연용 표시다.

## 실행

현재 컨테이너에 Flask와 QR 라이브러리를 설치했고 Dockerfile에도 반영했다.

```bash
# 첫 터미널: C 저장소 (이미 실행 중이면 다시 실행하지 않는다)
make server
./build/mini-redis-server
```

```bash
# 두 번째 터미널: 자리 선택 웹
make web
```

로컬 참여 주소는 `http://127.0.0.1:8090/`, 관리자는 `/admin`이다.
VS Code의 Ports 탭에서 8090을 전달하면 Windows 브라우저에서 볼 수 있다.
관리자 키는 터미널에서 다음 명령으로 확인한다.

```bash
cat data/web-admin.key
```

`data/web-session.key`는 참여자 세션 서명과 브라우저 소유권 식별에 사용한다.
웹 재시작 후에도 본인 자리를 알아보려면 이 파일과 C 로그를 함께 보존해야 한다.
이 두 키 파일의 내용은 소스 저장소나 참가자에게 공유하지 않는다.

## 참여와 배정 규칙

- 성명은 1~30자의 출력 가능한 문자열로 받고, 세 글자로 제한하지 않는다.
- 교육생 번호는 양의 정수로 식별한다. 실제 명단이 확정되지 않아
  30~70, 1~90 같은 추정 범위로 제한하지 않는다. 입력 크기 상한은 9999다.
- 이름·번호는 자기 신고이며 실제 본인 인증을 제공하지 않는다.
- 최초 등록한 번호는 성명과 해당 브라우저의 임의 토큰에 연결한다.
  다른 이름 또는 다른 브라우저에서 같은 번호로 등록하면 거절한다.
  동명이인은 서로 다른 번호로 참여할 수 있다. 모든 기기는 자리 현황을 공유하지만,
  일반 참여자의 확정·취소 권한은 등록한 브라우저에만 있다.
- 기기를 변경하거나 쿠키를 잃어버렸다면 관리자가 해당 자리를 먼저 취소하고
  번호 등록을 초기화해야 한다. 자리가 없으면 참여 정보 변경으로 스스로 등록을 해제할 수 있다.
- 이전 시제품 쿠키에는 브라우저 토큰이 없어 재참여해야 한다.
  기존 배정은 삭제하지 않으며 관리자가 취소한 후 다시 등록할 수 있다.
- 한 교육생 번호에는 한 개의 유효한 선점/배정만 허용한다.
  이 보장은 웹 서버 프로세스 하나를 실행하는 시연 구성에 해당한다.
- 같은 번호의 복수 요청은 웹의 번호별 락으로 조정하지만,
  서로 다른 교육생의 자리 경쟁은 C Mini Redis의 NX가 결정한다.
- 임시 선점은 C 저장소 기준 20초다. 화면 카운트다운은 표시용이며,
  실제 만료 판정은 저장소가 한다.
- 확정은 선점 ID·소유자·임시 상태 확인 후 전체 현재 값을 조건부 변경한다.
- 취소도 ID와 예상 상태를 확인하고 조건부 삭제한다.
  이전 화면의 취소가 새 선점이나 확정 상태를 지우지 못하게 한다.
- 공통 만료 시각은 관리자 설정 **이후 확정하는 배정**에 적용한다.
  기존 확정의 기한을 소급해서 변경하지 않는다.
- 사전 배정은 만료 없이 유지한다. 관리자가 취소하면 그 자리도 선택 가능해진다.
- 시작 완료 표시를 저장해 웹 재시작 시 취소된 사전 배정을 다시 채우지 않는다.
- C 저장소 응답을 못 받으면 실패로 단정하지 않는다. 화면을 다시 조회해
  본인 선점이 반영됐는지 확인한다. 저장소가 없으면 가짜 빈자리를 만들지 않는다.

## 관리자 화면

1. `/admin`에서 로컬 파일의 관리자 키로 인증한다.
2. 공통 만료 시각을 지정한다. `1분 후로 맞추기`는 초까지 보존한다.
3. 이후 확정된 배정은 그 시각에 만료된다. 회색 사전 배정은 그대로다.
4. 취소할 자리를 선택하거나 배치도에서 누른 뒤 관리자 취소를 실행한다.
5. 외부 접속 주소를 저장하면 참여용 QR이 표시된다.
6. 기기 변경이 필요하면 배정 취소 후 `번호 등록 초기화`를 사용한다.
7. 취소한 자리를 다시 채우려면 `기존 배정으로 되돌릴 빈자리`에서 고르고
   `기존 배정으로 되돌리기`를 누른다. 2팀-2·11팀-1과 공석은 제외하며,
   NX로 빈자리일 때만 만료 없는 기존 배정을 저장한다. 선점·확정된 자리는 덮어쓰지 않는다.

발표용 PC에서도 일반 자리 선점 페이지 `/`를 사용한다. 별도 발표 화면은 제거했고
이전 `/present` 주소는 `/`로 이동한다. 휴대폰에서는 전체 배치도를 화면 너비에 맞추고,
긴 이름은 작은 좌석 상자 대신 위쪽 현황 카드에 표시한다.

관리자 인증은 서명된 세션으로 유지하며, 일반 참가자는 관리자 API를 사용할 수 없다.
브라우저의 외부 Origin 변경 요청을 거절하고, 입력 크기·중복 JSON 항목·잘못된 자료형을 검사한다.
HTTPS 터널 요청에는 Secure 쿠키를 사용한다. HTML에 참가자 문자열을 삽입할 때는
textContent를 사용해 이름이 코드로 실행되지 않게 한다.

## 와이파이가 달라도 접속하기

발표용 외부 주소에는 Cloudflare Quick Tunnel을 사용한다.
별도 계정이나 도메인 없이 임시 HTTPS 주소를 제공하지만, 재실행할 때 주소가 바뀌며
프로세스 종료 시 접속할 수 없다. 가동 보장은 없는 개발·시연용 서비스다.
공식 문서: https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/

호스트 PowerShell에서 실행한다. `<컨테이너 ID>`는 현재 개발 컨테이너 ID다.

```powershell
docker ps
docker run --rm --name mini-redis-web-tunnel --network container:<컨테이너 ID> cloudflare/cloudflared:latest tunnel --no-autoupdate --url http://127.0.0.1:8090 --protocol http2
```

표시된 HTTPS 주소를 관리자 화면의 외부 접속 주소에 넣으면 QR이 갱신된다.
터널은 웹8090에만 연결하며 C 저장소8080은 외부로 직접 연결하지 않는다.
PC, Docker, C 서버, 웹 서버, 터널을 모두 실행 상태로 유지해야 한다.
중지하려면 호스트에서 `docker stop mini-redis-web-tunnel`을 실행한다.

## 검증

```bash
make web-test
```

별도 C 서버와 임시 로그를 사용하는 17개 연동 테스트다.
전체 배치도·빈자리2개, 짧은 성명과 번호 검증, 선점·확정·취소,
오래된 ID 거절, 여러 참가자의 경쟁, 동일 번호 중복 선점,
관리자 취소 후 재시작 시 재배정 방지, QR/설정/권한/입력 오류,
C 서버 강제 종료 후 소유자와 배정 유지, 중복 번호·다른 기기 제어 거절,
동명이인 허용, 등록 해제·이전 쿠키 거절, 이전 발표 주소의 이동까지 검사한다.

브라우저에서는 참여, 카운트다운, 자연 만료 후 빈자리 복귀,
휴대폰 크기 레이아웃과 외부 HTTPS 페이지 응답을 확인했다.
실제 휴대폰의 셀룰러 접속은 사용자의 기기로 최종 확인해야 한다.

API 응답 캐시와 성능 비교는 별도 `/menu` 화면에 구현했다.
사용법과 측정 범위는 [주간 식단 캐시](menu-cache.md)를 참고한다.
