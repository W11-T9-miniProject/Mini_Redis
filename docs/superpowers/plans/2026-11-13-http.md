# HTTP API Implementation Plan

**Goal:** 기존 저장소를 HTTP로 호출하고 결과와 오류를 명확히 구분한다.
**Architecture:** libmicrohttpd가 연결·본문 수신·응답 전송을 맡고 cJSON이 구조를 해석한다.
`src/server.c`가 입력을 검사해 공개 저장소 연산을 호출한다.
`src/json_input.c`는 cJSON의 관대한 문자·숫자 처리만 사전 검증한다.
**Tech Stack:** C11, libmicrohttpd, cJSON, Python 표준 라이브러리 기능 테스트.

## Contract

- 로컬 IPv4 loopback, 기본8080, 포트0 자동배정, 기본로그 data/mini-redis.aof.
- GET /health는 접속 확인, POST /kv는 JSON 명령.
- op: set/get/delete/compare_delete/compare_set. 필드와 상태 매핑은 docs/http-api.md에 명시.
- NX는 상대TTL, 일반 set과 조건부 변경은 절대 만료도 지원한다. 단위는 밀리초.
- 요청 최대64KiB, 중복·알 수 없는 필드·불일치 타입·잘못된 숫자·UTF8·제어문자·NUL 거절.
- 4개 작업 스레드, 최대연결256, 연결 비활성제한10초. 데이터는 기존 공통 락으로 보호.
- 입력과 출력은 기존 저장소의 메모리 소유권을 지킨다.
- 신호는 sigwait로 처리하고 HTTP 작업을 종료한 다음 테이블을 해제한다.
- raw API는 로컬 내부용이며 사용자/관리자 권한은 후속 웹 서버가 처리한다.
- 웹 화면·캐시·성능 비교는 이번 단계에 포함하지 않는다.
