# NX and Common Mutex Implementation Plan

**Goal:** 유효한 키가 없을 때만 저장하고, 모든 데이터 연산을 공통 락으로 보호한다.
**Architecture:** 테이블당 pthread mutex 하나를 둔다. 공개 함수가 락을 획득·해제하고,
내부 `_locked` 함수는 이미 락을 보유한 상태에서만 실행한다.
**Tech Stack:** C11, pthread mutex/barrier, GCC assert, ASAN/UBSAN.

## Rules

- `ht_set_nx(table, key, value, ttl_ms)`: TTL 0은 무기한, 양수는 상대 밀리초.
- 이미 유효한 키가 있으면 `HT_CONDITION_NOT_MET`를 반환하고 값과 기한을 유지한다.
- 만료 확인·삭제·NX 판단·저장·확장은 같은 임계 구역에 포함한다.
- 일반 저장·조회·삭제도 동일한 mutex를 사용한다. 조회 결과 복사도 락 안에서 한다.
- 상대 TTL의 기준 시각은 락을 획득한 뒤 계산한다.
- `_locked` 내부에서 락을 다시 획득하는 공개 함수를 호출하지 않는다.
- 락 획득 전에는 리해싱으로 바뀔 수 있는 buckets/capacity/size를 읽지 않는다.
- 초기화·해제는 다른 요청이 없는 상태에서 호출한다. 필드 직접 조회도 같은 조건이다.
- 뮤텍스 초기화·획득·해제 오류는 `HT_LOCK_ERROR`로 구분한다.
- 조건부 취소·확정, 로그, HTTP는 이번 범위 밖이다.
