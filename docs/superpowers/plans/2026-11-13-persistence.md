# Persistence Implementation Plan

**Goal:** 변경 결과를 디스크에 먼저 반영하고, 프로세스 강제 종료 후 복원한다.
**Architecture:** `src/log.c`가 기록·검증·파일 잠금·꼬리 복구를 맡는다.
저장소는 기존 공통 락 안에서 변경 조건 확인과 메모리 준비 후 로그를 반영하고,
그 이후 실패 가능한 할당 없이 메모리를 변경한다.
**Tech Stack:** POSIX read/write/fsync/ftruncate/flock, C11, 기존 테스트 도구.

## Contract and format

- `ht_init`는 기존 메모리 전용 모드, `ht_open(table, path)`는 파일 복원 모드.
- 초기화/해제는 작업 스레드가 없는 상태에서 수행한다. 파일당 한 프로세스만 연다.
- 파일 경로는 호출자가 지정하고 부모 디렉터리는 먼저 생성해야 한다.
- 헤더는 32바이트, 숫자는 little-endian이다.
  magic/version(4), operation(1), reserved(3), key length(4), value length(4),
  absolute expiry(8), header checksum(4), payload checksum(4) 순서다.
- 체크섬은 FNV-1a 32비트다. 헤더 처음 24바이트와 payload를 각각 검증한다.
- payload는 키 바이트와 값 바이트다. NUL은 파일에 저장하지 않고 복원 시 추가한다.
- 키+값은 최대 1MiB다. 로그에서 내장 NUL, 음수 범위의 만료값,
  잘못된 opcode/길이/체크섬은 손상으로 거부한다.
- 기록은 확정된 SET/DELETE 결과만 포함한다. NX나 비교 조건은 재평가하지 않는다.
- 실패한 조건은 기록하지 않는다. 지연 삭제는 원래 절대 만료 시각으로 재현 가능하므로 기록하지 않는다.
- 파일 write/fsync 실패는 HT_IO_ERROR를 반환하고 모든 후속 변경을 차단한다.
  읽기는 유지한다. 완전히 쓰였지만 fsync가 실패한 기록은 재시작 후 반영될 수도 있다.
- 메모리·입력 오류는 파일 I/O 실패와 다르므로 그 자체로 쓰기를 중단하지 않는다.
- 완전한 기록은 헤더와 payload를 모두 검증한다. 불완전한 마지막 기록만 절단·동기화한다.
  헤더 길이를 신뢰하기 전에 헤더 체크섬을 확인해 손상을 꼬리 잘림으로 오인하지 않는다.
- 복원 시 로깅과 중간 만료 검사를 억제한다. 최종 상태의 만료 항목을 제거한 뒤 요청을 받는다.
- 새 파일 경로의 보존을 위해 부모 디렉터리도 동기화한다.
- 로그 압축/회전, 실제 정전·디스크 고장 대응은 이번 구현에 포함하지 않는다.
