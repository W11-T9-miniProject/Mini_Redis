# Redis Market — 상품 조회 실험실

직접 구현한 `../c-mini-redis/mini-redis`만 사용하는 로컬 웹 서비스입니다. DBMS 영역은 빈 상태이며 DBMS 구현, 외부 DB 제품, mock DB, 캐시 미스 시 자동 복구가 없습니다.

## 실행

Node.js 18 이상이 필요합니다. C 서버가 아직 없다면 `cd ../c-mini-redis && make`로 먼저 빌드하세요.

```sh
cd /Users/dltmdwu130/mini-redis/product-demo
npm start
```

http://127.0.0.1:3000 에 접속하세요. C Redis는 기본 16380 포트로 실행되고, 기존 실습 데이터와 분리된 `.redis-data/`에 자체 RDB를 저장합니다. `Ctrl+C`는 웹 서버와 이 명령이 시작한 Redis를 함께 종료합니다. 추가 npm 패키지 설치는 필요 없습니다.

포트 변경: `WEB_PORT=3001 REDIS_PORT=6381 npm start`.
이미 실행한 **C Mini Redis**를 사용하려면 `REDIS_HOST=127.0.0.1 REDIS_PORT=6379 npm run web`. 이 모드는 Redis를 시작하거나 종료하지 않습니다. 상위 JavaScript Redis는 KEYS를 지원하지 않으므로 대상이 아닙니다.

## 시연

1. **샘플 상품 저장**을 클릭합니다. 이 버튼을 누를 때만 예제 상품 4개를 실제 Redis에 저장합니다. 같은 ID가 있으면 덮어씁니다.
2. 상품 카드나 **직접 조회하기**에서 ID `1001`을 조회합니다. 실제 GET 응답, HIT, 왕복 시간, JSON이 표시됩니다.
3. ID `missing`을 조회해 MISS를 확인합니다. DBMS로 넘어가지 않습니다.
4. 상품 등록 TTL을 `5`로 설정하고 샘플 저장 또는 새 상품 등록 후 5초 기다립니다. 상품이 사라지고 같은 ID를 조회하면 MISS가 됩니다.
5. 카드의 × 버튼은 해당 상품 키에만 DEL을 실행합니다.

상품 키 접두사는 `product-demo:product:`입니다. 주기적 상태 확인은 PING / KEYS * / GET / TTL을 사용하며 조회 통계와 명령 로그에는 포함하지 않습니다. 따라서 지표는 사용자가 실행한 상품 조회 GET만 셉니다. 응답 시간은 웹 서버에서 측정한 Redis TCP 연결·GET 응답 왕복 시간이며 브라우저 지연은 제외합니다. 조회 지표와 최근 80개 명령 로그는 웹 프로세스 메모리에만 보관되어 재시작 시 초기화됩니다. Redis 자체 TTL/RDB 동작은 기존 구현을 그대로 사용합니다.

웹은 127.0.0.1에만 바인딩됩니다. 외부 배포나 DBMS 연결은 포함하지 않습니다. 개발용의 작은 상품 목록을 대상으로 합니다.

## 검증

```sh
npm test
```
